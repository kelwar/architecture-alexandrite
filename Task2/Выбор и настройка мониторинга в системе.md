### Мотивация

На данный момент система имеет две основные проблемы: жалобы пользователей на затерянные во времени заказы с последующей потерей контрактов, а также, долгое открытие страницы оператора в MES.

Мониторинг позволит с помощью различных измерений понять поведение сервисов, выявить и устранить задержку в открытии страницы оператора, что должно существенно увеличить скорость обработки заказов.

### Выбор подхода к мониторингу

Для выявления причин задержки при загрузке страницы актуальных заказов будем использовать подход RED, т.к. он лучше всего подходит для мониторинга веб-сервисов и очередей.

Метрики:
1. Number of dead-letter-exchange letters in RabbitMQ - позволит выявить в качестве одной из причин задержки сбоящие сообщения в очереди. Ярлыки не требуются.
2. Response time (latency) for MES API - узнаем время ответа MES API на запрос MES во время загрузки страницы. Ярлыки не требуются
3. Number of simultanious sessions for MES API - проверка загруженности MES API во время долгой загрузки страницы.  Ярлыки не требуются

### План действий

1. Собрать данные метрик
2. Отправить данные в хранилище
3. Проанализировать данные
4. Сформировать отчёт
