Необходимо, в первую очередь, собирать логи уровня INFO в местах прохождения значимых запросов, связанных непосредственно с заказом:
1. Любое изменение статуса заказа, связанное с действиями пользователя.
2. Подтверждение готовности заказа к обработке со стороны CRM API.
3. Получение запроса системой MES API как от пользователей API, так и из очереди RabbitMQ.

Состав записи журнала:
1. Время события (таймстамп).
2. Номер заказа.
3. Название системы (например MES-API, Shop-API т т.д.)
4. Тип пользователя (Customer, Seller, Operator).
5. Идентификатор пользователя в системе.
6. Сообщение.

В случае выявления странного поведения системы, допустимо использовать логи уровня DEBUG в качестве временной меры для выявления и устранения причин возникновения странного поведения системы.

### Мотивация

Внедрение логирования позволит существенно снизить время на обработку пользовательских заявок в техподдержку. 
Большинство запросов сотрудник техподдержки сможет решить самостоятельно, не привлекая разработчиков.
Разработчикам потребуется значительно меньше времени на поиск и выявление причин неисправности, что в том числе скажется положительно на скорости внедрения нового функционала, а также улучшит пользовательский опыт взаимодействия с техподдержкой.

В первую очередь необходимо настроить логирование и трейсинг для систем CRM-API, MES-API, т.к. именно на этом участке на данный момент происходит задержка прохождения запросов.

### Предлагаемое решение

Диаграмма:
./jewerly_c4_model.drawio

Предлагается для организации логирования использовать стек ELK.
1. Filebeat будет собирать данные из сервисов CRM-API и MES-API и передавать в Logstash - конвейер данных.
2. Logstash передаёт данные на хранение в Elasticsearch.
3. Elasticsearch обменивается данными с Kibana - инструментом визуализации.

Доступ к логам уровня INFO должны иметь только сотрудники с ролью "Поддержка". Желательно избежать чувствительных данных в логах, заменив их на идентификаторы.

Будет использован отдельный индекс под систему. Срок хранения логов: 3 месяца, т.к. по жалобам пользователей некоторые заказы обрабатываются несколько месяцев. 
Более долгий срок хранения требует дополнительных существенных вложений в дисковое пространство и нецелесообразен.
Размер лог-файла - 128МБ.

Также, стоит настроить оповещение о важных событиях на электронную почту. Например, получение сообщения уровня ERROR.
Внедрение системы поиска аномалий, например с использованием ИИ, на данном этапе нецелесообразно. 
Достаточно ручного поиска аномалий.
